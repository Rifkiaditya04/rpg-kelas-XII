# Interpretation

Ada satu keputusan penting dari provenance pass ini:

**Kita tidak akan membuat soal hanya berdasarkan "topik surat lamaran".**

Setiap batch berikutnya harus memiliki hubungan:

```text
SOURCE
  ↓
CONCEPT
  ↓
SKILL
  ↓
INDICATOR
  ↓
COGNITIVE DEMAND
  ↓
QUESTION
  ↓
ANSWER
  ↓
EXPLANATION
  ↓
GAME MECHANIC
```

Dengan demikian, misalnya soal tentang kata baku tidak sekadar:

> "Mana kata yang benar?"

tetapi dapat dibuat menjadi situasi **Error Hunt** yang meminta siswa menemukan kesalahan dalam dokumen lamaran.

## ⚠️ Catatan provenance yang sengaja saya pertahankan

Anda sebelumnya menetapkan bahwa setiap klaim harus memiliki **nomor baris** jika tersedia.

Untuk file Markdown buku yang kita konversi, connector GitHub saat ini tidak memberikan nomor baris asli yang stabil untuk keseluruhan body sumber; karena itu saya **tidak mengarang nomor baris**.

Saya menggunakan:

> **nama file + halaman buku + subsection**

sebagai locator yang dapat diaudit.

Ini secara eksplisit saya dokumentasikan di provenance artifact.

Jadi kita tetap mengikuti prinsip:

**lebih baik `unverified line number` daripada nomor baris palsu.**
